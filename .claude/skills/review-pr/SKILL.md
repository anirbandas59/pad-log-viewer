# Review PR(s): $ARGUMENTS

1. **Select PRs.** If a number was given, review that PR. Otherwise list `gh pr list --label ready-for-review --json number` and review each one in turn.
2. **Cloud footer.** The `pr-body-footer` workflow removes the cloud proxy's trailing `---` / `_Generated by [Claude Code](…)_` footer from PR bodies automatically. If it is still there when you review, report it as a **Suggestion** (the workflow may not have run yet), not a Blocking finding. Any other attribution in the body is still a finding.
3. **Round limit.** For each PR, count prior reviews whose body contains `Verdict: REQUEST_CHANGES` (`gh pr view <PR> --json reviews`). If there are already 3, do not review again: run `gh pr edit <PR> --remove-label ready-for-review --add-label needs-human`, comment "3 review rounds reached; needs a human decision", and move on.
4. **Delegate.** Use the `reviewer` subagent for the PR, passing the PR number. It returns the full review text ending in `Verdict: APPROVE` or `Verdict: REQUEST_CHANGES`.
5. **Post.** Write the review body to a temp file and post it:
   - APPROVE: `gh pr review <PR> --approve --body-file <file>`
   - REQUEST_CHANGES: `gh pr review <PR> --request-changes --body-file <file>`
   - If GitHub refuses the approve/request-changes event (e.g. self-review), fall back to `gh pr review <PR> --comment --body-file <file>`.
6. **Relabel.** `gh pr edit <PR> --remove-label ready-for-review --add-label approved` or `--add-label changes-requested` to match the verdict (remove the opposite label if present).
7. Print one line per PR: number, verdict, number of Blocking findings.
